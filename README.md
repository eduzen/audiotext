# AudioText Telegram bot

A Telegram bot that receives audio and returns a transcript generated by a local Whisper model. Audio is downloaded to the VM, processed there, and deleted when processing finishes.

The default `tiny` Whisper model with CPU INT8 inference is intended for a CPU-only VM with 4 GB RAM. The first start downloads the model (roughly 75 MB); allow enough disk space for the model cache and temporary audio.

## Requirements

- [uv](https://docs.astral.sh/uv/) and Python 3.14.x
- A Telegram bot token from [@BotFather](https://t.me/BotFather)
- Internet access for Telegram and the first model download

## Install and run

From the repository root, run `just setup` if you have [just](https://just.systems/)
installed. This installs the locked dependencies and creates `.env` only if it
is missing. Set `BOT_TOKEN` in `.env`, then run `just run`.

Without `just`, run `uv sync --locked --python 3.14` and copy `.env.example` to
`.env` if it does not already exist. Set `BOT_TOKEN`, then start the bot with:

```sh
uv run --locked --env-file .env audiotext
```

You can also use `uv run --locked --env-file .env python -m audiotext.bot`.
`src/` is the source directory, not the module name.

## Development checks

Run `just check` to run the same checks as CI. To install the Git hook locally
and run it against all files:

```sh
uv run --locked prek install
uv run --locked prek run --all-files
```

On commit, prek runs Ruff (including its `UP` pyupgrade rules) and ty against the Python source. Both tools use the versions in `uv.lock`.

## Integration test

Run `just test` or:

```sh
uv run --locked python -m unittest discover -s tests -v
```

The test feeds a synthetic speech MP3 through the real Telegram application and
local Whisper, with only the Telegram HTTP transport faked. It checks the reply
and verifies that the downloaded MP3 is removed. No bot token is needed. The
first run downloads the `tiny.en` Whisper model unless it is already cached.
Set `AUDIOTEXT_TEST_MODEL` to a local faster-whisper model directory to run
without network access after dependencies are installed.

## Use

Send the bot a Telegram voice message, audio attachment, or audio document. It accepts common formats including MP3, M4A, WAV, FLAC, OGG/Opus, AAC, WebM, and WMA. The default upload limit is 20 MB, matching the hosted Telegram Bot API download limit. Transcriptions longer than Telegram's message limit are sent in multiple replies.

The model loads when the bot starts. Only one transcription runs at a time to keep memory use predictable. Files are kept in the system temporary directory and removed after processing, including when transcription fails.

## Configuration

Copy `.env.example` to `.env` and configure:

| Variable | Default | Purpose |
| --- | --- | --- |
| `BOT_TOKEN` | required | Telegram bot token |
| `WHISPER_MODEL` | `tiny` | faster-whisper model name or local model path |
| `WHISPER_DEVICE` | `cpu` | Inference device |
| `WHISPER_COMPUTE_TYPE` | `int8` | CPU quantization mode |
| `WHISPER_THREADS` | `2` | CPU inference threads |
| `MAX_UPLOAD_MB` | `20` | Maximum accepted attachment size |
| `TEMP_DIR` | system temp | Optional directory for temporary audio |
| `LOG_LEVEL` | `INFO` | Python logging level |

For a 4 GB VM, keep `tiny`, `cpu`, and `int8`. Larger models can need substantially more memory. Telegram's hosted Bot API limits file downloads; the 20 MB default cannot be raised unless you run a local Telegram Bot API server and adapt deployment/configuration accordingly.
